# CLAUDE.md

Developer guide for this Raycast extension (Kubernetes context manager). User-facing behavior is documented in `README.md`; release notes in `CHANGELOG.md`. `update_plan.md` is a historical planning document, the README and the code are authoritative.

## What this is

A Raycast extension (macOS) that reads and edits the kubeconfig YAML directly with the `yaml` package. There is no kubectl dependency, no shell execution and no file watcher: view commands reload on open or via the Refresh action, and the menu bar refreshes on a one-minute interval.

Stack: TypeScript (strict, ES2022), React 19, `@raycast/api` 2.x, `@raycast/utils` 2.x, Vitest 3.

## Module map (`src/`)

Kubeconfig layer
- `utils/kubeconfig-io.ts` read/write only. Parses to a yaml `Document`, remembers it against the returned object (WeakMap) so writes keep comments and formatting, writes atomically (temp file + fsync + rename), preserves file mode (0600 for new files), follows symlinks, holds `<kubeconfig>.lock` (same file kubectl uses; about 0.5 s of retries, stale locks are never removed), refuses to write when mtime/size changed since the read, when the path changed, or when the config shape is invalid. Also owns the `KubeConfig` type. No backup file.
- `utils/kubeconfig-direct.ts` context operations built on the io layer: list, switch, set namespace, create, modify, delete, cluster/auth metadata, `loadKubeconfigState()` (one read producing everything a view needs).
- `utils/kubeconfig-path.ts` path resolution: preference, first `$KUBECONFIG` entry, `~/.kube/config`.
- `utils/kubeconfig-errors.ts` `KubeconfigError` and `ValidationError`, both with an optional `.action` (next-step hint). `utils/errors.ts` turns any error into a toast (`showErrorToast`, accepts `unknown`, never throws).

Switching and state
- `utils/switch.ts` `switchAndClose(perform, opts)`: the single switching path. Production confirmation, previous-context / recents / recent-namespace bookkeeping, HUD or toast per `closeAfterSwitch`, `closeWindow: false` for the menu bar (always HUD). Resolves to `false` on failure or cancellation.
- `utils/environment.ts` production pattern (`productionPattern`, default `prod|prd|live`, case-insensitive regex on the context name; empty disables; invalid falls back to the default and is reported once).
- LocalStorage-backed: `utils/recents.ts` (recent contexts, max 5; pins, max 20), `utils/recent-namespaces.ts` (per context, max 5), `utils/previous-context.ts` (key `previousContext`), `utils/context-storage.ts` (`migrateContextName`, used on rename). Reads distinguish a failing storage read (writes must abort) from missing/corrupt data (resets).

Pure helpers (no `@raycast/api`): `cloud-provider.ts` (EKS/AKS/GKE), `namespace.ts` (RFC 1123 label), `context-sections.ts` (Pinned/Recent/All), `context-forms.ts` (form validation, update diff, delete summary), `previous-switch.ts`, `menu-bar-title.ts`, `kubectl-command.ts`, `markdown.ts`.

UI
- `hooks/useKubeconfig.ts` one `useCachedPromise` around `loadKubeconfigState`, keyed by the resolved kubeconfig path; a load error hides cached data. Switch operations go through `mutate` (optimistic, rolled back on error, errors rethrown).
- `hooks/usePinnedRecent.ts`, `hooks/useProductionMatcher.ts`.
- `components/` `ContextActions` (copy/open actions), `ContextDetails`, `KubeconfigEmptyView` (error, empty and no-match states), `NamespaceSelector`, `context-visuals.ts` (icons, accessories, keywords, sorting).

## Design rules

- Pure modules must not import `@raycast/api`, so they stay unit-testable. `vitest.config.ts` aliases `@raycast/api` to an empty stub (`src/utils/__tests__/raycast-api-stub.ts`); tests that need the API mock it with `vi.mock`, and mock `../preferences` instead of reading real preferences.
- Only `kubeconfig-io.ts` writes the kubeconfig. Pass the object returned by `readKubeconfig` back to `writeKubeconfig`; a copy (`{...config}`, `structuredClone`) loses comment preservation and the conflict check. Do not add keys on read (writes must not add `contexts: []` to a file).
- Readers must tolerate missing nested maps (`context:`, `cluster:`, `user:`) and `null` list sections; the read step rejects non-list sections and nameless entries with a clear `KubeconfigError`.
- Mutations throw typed errors with an `action`; UI code catches and calls `showErrorToast`. Do not return `false` for failure.
- All switching goes through `switchAndClose`; never call the switch operations directly from UI code (that would skip the production guard and bookkeeping).
- LocalStorage helpers never throw and log failures; a failed read must never be followed by a write of empty data.
- Anything user-visible about a context is keyed by its name. Renames must call `migrateContextName`.
- Never do side effects (toasts, storage writes) during React render; use effects or handlers.
- Raycast conventions: Title Case for titles and actions, `Keyboard.Shortcut.Common.*` where one exists, `List.EmptyView` for empty/error states, HUD when the window closes or there is no window, toast otherwise, no emoji in UI or manifest text, `platforms` is `["macOS"]`.
- Keep docs honest: do not claim features the code does not have. Update README, CHANGELOG and this file with behavior changes.

## Development

```bash
npm install
npm run dev        # ray develop
npm run build      # ray build -e dist (also regenerates raycast-env.d.ts)
npm run lint       # ray lint (validates manifest, icons, metadata, ESLint, Prettier)
npm run fix-lint   # ray lint --fix
npm test           # vitest run
./node_modules/.bin/eslint src   # faster lint than ray lint
```

Adding a command: declare it in `package.json` (Title Case title, plain description, mode), add the entry file under `src/`, run `npm run build` to regenerate types, document it in README and CHANGELOG. Adding a preference: declare it in `package.json`, read it through `utils/preferences.ts`.

Tests live in `src/utils/__tests__/` (Vitest). The I/O tests use real temp directories, not fs mocks. Prefer extracting logic into a pure helper over testing UI components (there is no component test setup).

## Verification checklist

Before committing:

1. `npx tsc --noEmit`
2. `./node_modules/.bin/eslint src`
3. `./node_modules/.bin/prettier --check src`
4. `npm test`
5. `npm run build`
6. `npm run lint` before a release (`ray lint`)

CI (`.github/workflows/ci.yml`) runs steps 1-5 on Node 22. Dev-only files (`CLAUDE.md`, `update_plan.md`, tests, `.github/`, `vitest.config.ts`) are excluded from the published package via `.raycastignore`.

## Known limitations

- One kubeconfig file: no multi-file merge; with no preference set only the first `$KUBECONFIG` entry is used.
- Namespaces are the common ones, those found in the kubeconfig and anything typed; there is no live cluster lookup.
- Nothing has been exercised inside Raycast by automated tests; UI changes need a manual pass in `npm run dev`.
- `npm audit` reports one moderate advisory in the dev-only vitest 3.x (fix needs 4.1.11+, blocked by an npm resolver error); production dependencies are clean.
- Screenshots in `metadata/` predate the menu bar command and the Pinned/Recent layout.
